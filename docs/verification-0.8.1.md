# Verification — 0.8.1

The learner screen shows a short Codex explanation and code verified against an actual recorded edit, without a quiz. Existing public prose is eligible only as labelled context: it must name the exact relative file path, immediately precede that edit in the same turn, and belong to a registered worktree. Nearby commentary without a file reference is deliberately insufficient. Operational instructions and unrelated replies are excluded.

The parser bounds fields, code size and line count, rejects unsafe source paths and generated/test artifacts, and checks relative indentation. Explicit file additions are normalized from Codex's literal added-file records. Removed worktrees require exact historical absolute paths and matching patch excerpts; comparisons use immutable virtual documents without reading the removed filesystem.

The old primary request button and repeated empty-screen instructions are removed. Existing explanations open directly; additional requests are under ⋯ and open a review before sending. Closing that review sends nothing. The old button copied a prompt and opened a deep link despite implying delivery. It now uses the official `codex queue --thread … --message … --resume` command only after explicit send confirmation to the captured chat ID. Sending, queued, unsupported, failed and uncertain states are distinct. In-flight, queued and uncertain requests block duplicate clicks. A request identifier correlates the original owner's response. No automatic retries, independent agent, direct model API call, model override, credential access or persistent learning memory are added. Startup, refresh, selection and notifications remain read-only.

Regression checks reproduce pointer hover in the browser engine and assert primary-button colors and enabled state during history loading. They also exercise request review, cancellation, stale-chat rejection, exact argument handling, command incompatibility, delivery failures, timeouts, duplicate clicks, response identifiers, malicious card text, source anchoring, unrelated turns and worktrees, and preserved read-only comparisons. The optional editing guide keeps its frame during source handoffs while hiding prediction controls until native focus completes. UI checks cover Korean/English, three themes and three widths, including request review, pointer hover and request states. UI command-dispatch checks alone are not described as end-to-end host verification.

Real-chat checks read the changing **홈 추천과 New 구현 확인**, **로컬라이재이션 대응**, and **GCP 청구 알림 원인 확인** chats. They include a long multi-worktree task without a qualifying explanation, a previously authored explanation with a deleted worktree, and analysis with no code edit. No new message is sent in these checks, as requested by the user. Consequently, live delivery and a new end-to-end owner response are not verified by this run. The existing real explanation is not presented as evidence that other chats already have one. Private reports and screenshots remain under ignored artifacts.

Native-host checks verify immutable comparisons and source preservation. CI also exercises the optional imported-plan, editing, checking and decision flows through their current command-palette entry points. Fixtures and layout screenshots alone do not prove live message delivery, code correctness or a learning outcome.

Button verification is separated by boundary: the real-chat reader and browser cover task selection, existing content, request review/cancel and comparison dispatch; native VS Code checks cover immutable comparison documents; host contract checks cover the exact deep link and its launch-failure branch, plus stale request rejection. A new live send is intentionally not performed. Configuration controls are not considered verified merely because a command is registered.
